## Matching-version trace and repair scope

In the installed 0.85.1 source map, `src/tui-alt-screen.ts:274` installs the viewport listener at construction. `src/tui.ts:894-902,1006-1081` runs listeners in insertion order before focused dispatch, with terminal color protocol response guards first and cell-size response, debug key, overlay focus recovery and focused dispatch after listeners. `src/tui-alt-screen.ts:656-768` consumes focus/mouse protocols and search keys before reaching `shouldDeferViewportInputToOverlay()` at `:723`; only then does it match and consume page, half-page, line, prompt and top/bottom transcript navigation. The published `dist/tui-alt-screen.js:538-548` exhibits the same page-key precedence. The installed Host `dist/modes/interactive/interactive-mode.js:1861-1878,1903` maps `onTerminalInput` to a later `ui.addInputListener`; Todo adds/removes it in `packages/todo/src/widget.ts:68-93`. This is the preemption chain in both versions, not version parity.

**Recommended bounded implementation on a verified 0.85.1 Host source checkout (or an explicitly selected newer target):** move only the fullscreen *keyboard viewport navigation* group behind ordinary input listeners and ahead of focused-component dispatch, while keeping viewport-owned focus, mouse/selection, and search handling in their existing early stage. A protected unconsumed-input hook in `TuiBase` plus a split `TuiAltScreen` handler is one concrete source-level shape; retain terminal protocol guards and pass the transformed nonempty data to the hook. Do not just move the entire viewport handler behind extensions: an extension could swallow focus-out cleanup, mouse capture release/selection, or search ownership. Do not move the full handler after focused input: transcript paging would reach the editor first. Keep `shouldDeferViewportInputToOverlay()` in the keyboard fallback, and check overlay focus after any listener-induced focus transition. Treat configured viewport bindings, press/release symmetry, search shortcuts, and regular-screen behavior as regression surfaces.

A non-overlay selector is a separate hazard: installed Host `dist/modes/interactive/interactive-mode.js:1976-1988` focuses `ExtensionSelectorComponent` without an overlay. `shouldDeferViewportInputToOverlay()` alone cannot protect a selector's PageUp/PageDown from a fallback viewport handler; that conflict already exists in current ordering, but changing priorities must not claim selector page ownership is solved. The tested Todo listener retires on unhandled opening chords (e.g. Ctrl+L) before Host dispatch (`packages/todo/src/widget.ts:81-88`); verify picker Down and first Escape remain owned by picker, and explicitly test picker page keys. If selector page ownership is required, the Host must expose or apply focused-modal priority explicitly rather than treating every non-overlay focus as editor. A background modal opening without a Todo handoff chord is likewise not proved isolated by this routing repair.
