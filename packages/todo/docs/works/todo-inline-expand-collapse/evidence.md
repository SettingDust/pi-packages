The original failed implementation registered `onTerminalInput` before focused Host dispatch. It kept the Todo listener active on passthrough keys; after Ctrl+L opened the picker, Todo still consumed Down and Escape first. The public UI API has no focused-surface query, so the correction retires Todo interaction on the first non-Todo key (including the opening bracketed-paste marker) **before** forwarding that input to Host. Key-release sequences leave Todo active. Escape while Todo still owns input ends Todo interaction as before; after a passthrough handoff, the foreground surface receives navigation and the first Escape. Reenter with `/todo-details` or the configured Todo shortcut; the canonical Todo snapshot and same-session expansions remain mounted. A plain editor keystroke also ends Todo interaction, and unbracketed paste that equals a Todo key remains indistinguishable at this public input boundary.
