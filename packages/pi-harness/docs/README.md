# @settingdust/pi-harness Documentation

This directory is authoritative for the `@settingdust/pi-harness` package.

- `prd/`: product scope, outcomes, and non-goals.
- `adr/`: accepted architectural decisions and their consequences.
- `proposals/`: draft candidate decisions that are not authority until accepted and reconciled into an ADR or Spec.
- `spec/`: normative behavioral and interface contracts; draft candidate Specs state their non-authoritative status explicitly.
- `works/`: active work context, unresolved questions, and implementation planning.
- New planned work uses the Work/Context/Plan/Waves tuple; historical Tasks remain compatibility records only.

When documents conflict, apply this precedence: ADR decisions constrain Specs; Specs constrain Plans and their executable Waves graphs; PRD defines product scope. Historical Tasks are compatibility records and do not define new planned execution. A completed decision belongs in an ADR or Spec, not only in a Work Context.
